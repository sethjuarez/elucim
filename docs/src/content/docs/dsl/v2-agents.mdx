Elucim v2 is the agent-friendly document layer for host apps that want generated diagrams to be easy to patch, refine, and preview. The current renderer/editor still support v1 documents, while v2 adds a normalized structure and compatibility helpers so hosts can adopt it incrementally.

## Document shape

V2 documents are normalized by stable element ID:

```ts
import type { ElucimV2Document } from '@elucim/dsl';

const doc: ElucimV2Document = {
  version: '2.0',
  scene: {
    type: 'player',
    width: 1920,
    height: 1080,
    children: ['headline', 'metric'],
  },
  elements: {
    headline: {
      id: 'headline',
      type: 'text',
      layout: { x: 120, y: 120 },
      props: { type: 'text', content: 'CutReady impact' },
    },
    metric: {
      id: 'metric',
      type: 'text',
      layout: { x: 120, y: 260 },
      props: { type: 'text', content: '42% faster' },
    },
  },
};
```

Agents should make stable IDs part of their output contract. That lets a host app ask for precise edits like “update `metric`” instead of regenerating the whole slide.

## Compatibility path

Use normalization and renderability helpers to bridge legacy, v1, and v2 documents:

```ts
import { normalizeToV2, toRenderableV1, validateForAgent } from '@elucim/dsl';

const normalized = normalizeToV2(inputDoc);
const validation = validateForAgent(normalized.document);
if (!validation.valid) throw new Error(validation.errors.map(e => `${e.path}: ${e.message}`).join('\n'));

const renderable = toRenderableV1(normalized.document);
```

The visual editor can open v2 initial documents and JSON imports by converting them to the current v1 editor model. When initialized with v2, use `onV2DocumentChange` to persist a v2-compatible result and `onV2CompatibilityWarnings` to surface rename, deletion, or pruning warnings in the host app. The editor preserves v2 metadata, element intent, timelines, and state machines where possible, and now exposes basic v2 timeline, state-machine, metadata, intent, and nudge review controls.

## Command surface

Host apps and agents should use `applyCommand()` for deterministic edits:

```ts
import { applyCommand } from '@elucim/dsl';

const updated = applyCommand(doc, {
  op: 'updateElement',
  id: 'metric',
  patch: {
    props: { content: '51% faster' },
    layout: { x: 160, y: 280 },
  },
});
```

Commands are pure: the input document is not mutated. Current commands cover adding, updating, deleting, moving, reparenting elements, animation presets, timeline upserts/previews, and metadata updates.

## Agent services

Use the document services to give agents compact context and repairable feedback:

```ts
import { diffDocuments, summarizeDocument, validateForAgent } from '@elucim/dsl';

const summary = summarizeDocument(doc);
const validation = validateForAgent(doc);
const patch = diffDocuments(before, after);
```

`validateForAgent()` returns structured validation errors plus repair hints. `diffDocuments()` returns JSON-patch-shaped operations that are useful for review, logging, and host approval flows.

## Timelines and state machines

V2 timelines are keyframe clips over a small safe property set: `opacity`, `translate`, `scale`, `rotate`, `fill`, and `stroke`.

```ts
import { applyTimelineFrame, transitionStateMachine } from '@elucim/dsl';

const previewDoc = applyTimelineFrame(doc, 'intro', 18);
const nextState = transitionStateMachine(doc, 'deck', 'idle', 'start');
```

State machines use a Rive-inspired but intentionally small model. Every machine has a visual **Entry** node, `entry` matches the explicit Entry transition target, `states` point at timelines, and machine-level `transitions` connect states. The Entry transition declares how the machine leaves Entry: `onStart` fires automatically when a preview/run begins, while events like `onClick` or `onKey` can intentionally gate the first state. A trigger transition fires when its `trigger` event is activated; an `exitTime` transition is the automatic **Next** path after the source state's timeline finishes. A transition whose target is `entry` resolves through Entry again, while a transition whose target is `exit` reaches the terminal **Exit** pseudo-node and stops that machine.

The minimal event presets are `onStart`, `onClick`, `onKey`, and `reset`. Use `onKey` plus `key` metadata for keyboard interactions such as Enter, Space, Escape, or ArrowRight; key matching is case-insensitive, so `G` and `g` are the same binding. `reset` is still a normal event transition; the convention is to target `entry`, then let Entry decide whether to restart immediately (`onStart`) or wait for its gated start event. Use a custom trigger name for domain events the host app sends, such as `back`, `timeout`, `answerCorrect`, or `dataLoaded`; custom names have no special behavior beyond matching the event string.

```ts
stateMachines: {
  deck: {
    id: 'deck',
    entry: 'idle',
    inputs: {
      start: { type: 'trigger' },
      reset: { type: 'trigger' },
    },
    states: {
      idle: { timeline: 'intro' },
      focus: { timeline: 'focus' },
    },
    transitions: [
      { id: 'entry-start', from: 'entry', to: 'idle', trigger: 'onStart' },
      { id: 'idle-start', from: 'idle', to: 'focus', trigger: 'start' },
      { id: 'focus-reset', from: 'focus', to: 'entry', trigger: 'reset' },
      { id: 'focus-next', from: 'focus', to: 'exit', exitTime: 1 },
    ],
  },
}
```

Scenes do not own duration in v2. Timeline durations are scoped to the state being previewed; during state-machine playback, the active state's timeline duration controls when **Next** auto-runs. Fixed-frame output must use an explicit export policy such as a selected timeline, selected state, scripted machine path, or machine run with a max-frame cap.

State-machine visual previews are composed as an ordered frame stack: all timelines are first applied at their start frame, then completed states and the active state overlay later in path order. If a timeline appears more than once in that stack, the later frame wins.

Editor graph positions are optional metadata under `layout`: `layout.entry` stores the visual Entry node, `layout.states` stores state node positions, and `layout.viewport` stores the graph pan/zoom. Multiple state machines are independent interaction controllers over the same scene/timelines; a host chooses which machine is active for a given surface or interaction mode.

## Deterministic nudges

Elucim does not call an LLM. Host apps such as CutReady can ask Elucim for deterministic nudges, show them to an agent or human, and apply the exact command list:

```ts
import { applyNudge, suggestDocumentNudges } from '@elucim/dsl';

const nudges = suggestDocumentNudges(doc);
const polished = applyNudge(doc, nudges[0]).document;
```

Initial nudges cover safe metadata polish, predictable root layer ordering, and a reviewable staggered intro clip. This gives agents a simple workflow: generate the 80% layout, ask Elucim for refinements, then apply or explain the chosen command-backed nudges.
